# Post-MVP Roadmap — DOCX v1.1 F4–F7

These phases were previously deferred. The founder has now explicitly
authorized their incremental implementation through separate handoffs. Live
credentials, marketplace terms, production traffic and binding actions remain
human-gated.

## F4 — Self-healing collectors

Classify parser, network, auth, proxy, semantic and source failures; let an AI
Marketplace Specialist propose connector-scoped patches; require fixtures,
historical replay, canary metrics, repair budgets and rollback. The maintainer
must not edit the domain core or permissions autonomously.

## F5 — Auction intelligence

Version lots and edital documents, estimate total cost, monitor live events and
surface legal/physical/operational uncertainty. The system informs and
organizes; the user remains responsible for due diligence.

## F6 — Negotiation assistance

Build a context package with listing evidence, market value, seller pressure,
target and an explicit user limit. Messages and follow-ups remain policy-bound;
a refusal is contextual history, not a permanent seller rule.

## F7 — Local action and control plane

Introduce a local user-plane agent for authenticated sessions and a signed,
idempotent authorization envelope. Buying, bidding or other binding actions
must pass deterministic checks for listing, price, total cost, expiry and
duplicate execution. AI recommendations are never authorization.

## Entry gates

- F0–F3 acceptance is complete and production boundaries are reviewed.
- Security review covers secrets, prompt injection, auditability, replay and
  user authorization.
- Each phase has a separate implementation task, tests and deployment review.
