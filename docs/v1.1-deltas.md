# DOCX v1.1 — Delta from the Existing Project

This note records what is reused, generalized or deferred while adapting the
existing Project Scout implementation to the strategy document.

## Reuse

- The TypeScript monorepo, Supabase migrations/RLS, authenticated Worker
  routes, collection queue contract, raw R2 addressing and eBay official
  adapter remain the implementation baseline.
- Deterministic intent interpretation and textual analysis remain valid as
  bounded local providers; no live LLM is implied by the new strategy.
- Existing privacy deletion and credential boundaries remain mandatory.

## Generalize

- eBay-only collection contracts become vendor-neutral while preserving the
  eBay adapter as the reference implementation.
- Listing identity expands from a source-specific listing to source identity
  plus canonical product evidence; raw, normalized and derived layers remain
  separate.
- Collection expands from a single adapter to layered source strategies and
  semantic health checks.
- The old milestone roadmap is reorganized as F0 Core, F1 three sources, F2
  Search Intelligence and F3 Opportunity.

## Add incrementally

- Event facts for listing and market changes.
- Mercado Livre official API boundary and Xianyu source boundary.
- Query families, product identity confidence, current valuation, liquidity and
  seller pressure.

## Explicitly deferred

Self-healing AI Maintainers, auctions, negotiation, local GUI/action agents,
deterministic execution authorization, live multimodal analysis and production
traffic remain deferred. See `docs/post-mvp-roadmap.md`.

## Important mismatch

The DOCX names Mercado Livre and Xianyu as F1 sources. The legacy project rules
were eBay-only. The refactoring adopts the DOCX scope only for the staged F1
work; it does not authorize unrelated marketplaces or a broad connector
factory. Each new source still requires a reviewed contract, fixture suite,
health checks and an explicit enablement decision.
